# NEBULA AI — Telegram bot starter

## Что уже есть
- Генератор сюжетов: зомби, блэкаут, расследование, выживание и случайный режим.
- Генератор промтов.
- Команда `/ask` для подключения ИИ через совместимый Chat Completions API.
- Роли: владелец, заместитель, администратор, пользователь.
- Защищённые команды управления ролями.
- Админ-панель Telegram: `/admin`.
- SQLite база пользователей и статистика.
- Webhook-режим для Render Free Web Service.

## 1. Создай бота
1. Открой Telegram и найди `@BotFather`.
2. Создай бота через `/newbot`.
3. Скопируй токен. Не отправляй его в чаты и никому не показывай.

## 2. Узнай свой Telegram ID
Добавь переменную `OWNER_ID` в Render. Узнать ID можно через собственного бота командой `/id` после первого запуска, либо через проверенного ID-бота.

## 3. Render (бесплатный Web Service)
1. Создай GitHub-репозиторий и загрузи все файлы проекта.
2. В Render выбери **New → Blueprint** и подключи репозиторий.
3. Render прочитает `render.yaml`. Создаст Web Service на бесплатном плане, если он доступен для аккаунта/региона.
4. В Environment добавь:
   - `BOT_TOKEN` — токен от BotFather
   - `OWNER_ID` — твой числовой Telegram ID
   - `WEBHOOK_SECRET` — случайная строка из букв, цифр, `_` и `-` (не менее 32 символов)
   - `AI_API_KEY` — необязательно, ключ совместимого ИИ API
5. После первого деплоя добавь `RENDER_EXTERNAL_URL` со значением hostname сервиса Render без `https://`, например `имя-сервиса.onrender.com`, затем сделай redeploy.
6. Проверь адрес `https://ИМЯ-СЕРВИСА.onrender.com/health`: должен вернуть `{"status":"ok","service":"NEBULA AI"}`.
7. Открой бота в Telegram и отправь `/start`.

## 4. Команды
- `/admin` — панель управления.
- `/deputy TELEGRAM_ID` — назначить заместителя (только владелец).
- `/grantadmin TELEGRAM_ID` — назначить администратора (только владелец).
- `/removeadmin TELEGRAM_ID` — снять роль (только владелец).
- `/id` — показать свой Telegram ID.
- `/ask текст` — запрос к ИИ (требуется API-ключ).

## Важные ограничения бесплатного хостинга
- Бесплатный Render Web Service засыпает после периода без входящих запросов. Telegram webhook может разбудить сервис, поэтому первый ответ после простоя иногда задерживается.
- Файловая SQLite-база на бесплатном Render не является постоянным хранилищем: при перезапуске или новом деплое данные могут потеряться. Для постоянных ролей и пользователей подключи PostgreSQL.
- ИИ-функция требует отдельный API-ключ. Telegram Premium друга не даёт API-доступ к ИИ.
- Не публикуй `.env`, токен Telegram или AI API-ключ.

## Локальный запуск
```bash
pip install -r requirements.txt
cp .env.example .env
# заполни BOT_TOKEN, OWNER_ID и WEBHOOK_SECRET
```
Для локального запуска через polling используй `python bot.py`; для Render запускается webhook через `app.py`.
